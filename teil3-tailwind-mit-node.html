Tailwind mit Node — Architektur & eigenes Setup

Der Play-CDN aus Teil 2 war nur zum Reinschnuppern gedacht. Jetzt bauen wir ein echtes Tailwind-Projekt mit Node.js: eine feste dist/main.css-Datei, die nur die wirklich verwendeten Klassen enthält — und ein Watcher, der sie bei jedem Speichern automatisch neu erzeugt.

1. Warum reicht der Play-CDN nicht mehr?

Erinnerung aus Teil 2: der Play-CDN kompiliert bei jedem Seitenaufruf im Browser neu und liefert nie exakt die Klassen, die man später wirklich braucht. Für ein echtes Projekt will man stattdessen eine fertige, kleine CSS-Datei, die einmal — oder automatisch bei jeder Änderung — auf dem eigenen Rechner gebaut wird. Dafür braucht es Node.js: eine JavaScript-Laufzeitumgebung ausserhalb des Browsers, mit der sich genau dieser Bauprozess ausführen lässt.

2. Die Architektur: vom HTML zur fertigen CSS-Datei

Drei Werkzeuge arbeiten dabei zusammen: npm installiert und verwaltet sie, Tailwind generiert die Utility-Klassen, PostCSS reicht das Ergebnis durch eine kleine Pipeline weiter. Der Ablauf sieht so aus:

Quelle index.html

Enthält die Tailwind-Klassen im Markup, z.B. md:grid-cols-3.

→
Scan Tailwind Engine

Durchsucht die in content (tailwind.config.js) angegebenen Dateien nach benutzten Klassennamen.

→
Build PostCSS-Pipeline

Tailwind selbst ist ein PostCSS-Plugin. Zusätzlich: autoprefixer, ggf. cssnano zum Verkleinern.

→
Ergebnis dist/main.css

Enthält nur die Basis-Styles + genau die Klassen, die im HTML tatsächlich vorkommen.

Diese fertige Datei wird ganz normal per <link rel="stylesheet"> im HTML eingebunden — kein <script>-Tag zur Laufzeit mehr nötig.

3. Der Watcher: automatisch neu bauen bei jeder Änderung

Warum reicht "einmal bauen" nicht?

Während der Entwicklung ändert man laufend Klassen im HTML. Ohne Watcher müsste man nach jeder Änderung von Hand den Build-Befehl neu ausführen. Ein Watcher beobachtet die Quelldateien im Hintergrund und stösst den Build automatisch an, sobald sich etwas ändert — man muss nur speichern und den Browser aktualisieren (oder Live Server macht auch das automatisch).

4. Ein eigenes Projekt aufsetzen — Schritt für Schritt

01

Projektordner + npm initialisieren

Legt eine package.json an, die alle Abhängigkeiten und Skripte des Projekts verwaltet.

mkdir mein-projekt && cd mein-projekt
npm init -y
02

Tailwind & PostCSS installieren

Werden lokal im Projekt installiert (Ordner node_modules/), nicht global auf dem Rechner.

npm install -D tailwindcss postcss postcss-cli autoprefixer
03

Config-Dateien erzeugen

Erstellt tailwind.config.js mit Grundgerüst.

npx tailwindcss init
tailwind.config.js — anpassen:
module.exports = {
  content: ['./index.html'],
  theme: { extend: {} },
  plugins: [],
}
postcss.config.js — neu anlegen:
module.exports = {
  plugins: {
    tailwindcss: {},
    autoprefixer: {},
  },
}
04

Input-CSS-Datei anlegen

Diese drei Zeilen ziehen die Tailwind-Layer (Grundreset, Komponenten, Utilities) in die eigene CSS-Datei.

css/input.css:
@tailwind base;
@tailwind components;
@tailwind utilities;
05

Build- & Watch-Skripte in package.json

Zwei Varianten: einmal bauen, oder dauerhaft beobachten.

"scripts": {
  "build-css": "postcss css/input.css -o dist/main.css",
  "watch-css": "postcss css/input.css -o dist/main.css --watch"
}
npm run watch-css
06

CSS im HTML einbinden

Ab jetzt einfach index.html speichern — der Watcher baut dist/main.css automatisch neu.

<link rel="stylesheet" href="dist/main.css">
Zum Ausprobieren
  • Führt die Schritte oben in einem leeren Ordner aus und startet npm run watch-css.
  • Öffnet index.html mit Live Server, fügt eine Klasse wie bg-red-600 hinzu und speichert.
  • Schaut euch dist/main.css an — die neue Klasse taucht dort automatisch auf.

5. Typische Ordnerstruktur danach

package.jsonAbhängigkeiten + Skripte (build-css, watch-css)
node_modules/installierte Pakete (nie von Hand bearbeiten, nicht ins Git einchecken)
tailwind.config.jswelche Dateien gescannt werden, eigenes Theme
postcss.config.jsPostCSS-Plugin-Pipeline
css/input.cssQuelle: @tailwind-Direktiven + eigenes CSS
dist/main.cssgeneriert — dieses File bindet man im HTML ein
index.htmlMarkup mit Tailwind-Klassen
Mitnahme aus Teil 3 Du verstehst die Kette HTML → Tailwind-Scan → PostCSS → fertiges CSS, kennst den Zweck des Watchers und hast ein minimales Tailwind+Node-Setup selbst aufgesetzt.
