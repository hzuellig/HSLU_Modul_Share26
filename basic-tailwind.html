Tailwind Basics — die Schreibweise verstehen

Achtung, wir arbeiten mit Version 3, https://v3.tailwindcss.com/

Bevor es mit p5.js weitergeht, lohnt sich ein kurzer Blick auf die Tailwind-Syntax selbst: Was bedeuten Klassen wie sm:grid-cols-2, hover:bg-blue-700 oder focus:ring-2? Diese Seite gibt einen kompakten Überblick über die wichtigsten Konzepte, keine vollständige Referenz.

1. Utility-First: viele kleine Klassen statt einer grossen

Statt eine eigene CSS-Klasse wie .card zu schreiben und darin Regeln zu sammeln, kombiniert man in Tailwind viele kleine, fertige Utility-Klassen direkt im HTML — jede macht genau eine Sache.

Klassisches CSS eigene Klasse

.card { padding:1rem; border-radius:0.5rem; box-shadow:...; } — Regeln stehen in einer separaten Datei.

↔
Tailwind Utility-Klassen

class="p-4 rounded-lg shadow" — jede Klasse setzt genau eine CSS-Eigenschaft, direkt im Markup sichtbar.

Der Name folgt meist dem Muster eigenschaft-wert: p-4 = padding: 1rem, bg-blue-600 = ein bestimmter Blauton als Hintergrund, rounded-lg = grosser Radius für abgerundete Ecken. Die genauen Werte definiert Tailwinds Standard-Theme (in tailwind.config.js anpassbar).

2. Responsive Design: die Präfixe sm: md: lg:

Tailwind ist mobile-first: eine Klasse ohne Präfix gilt immer, ab einer bestimmten Fensterbreite kann eine zusätzliche, überschreibende Klasse mit Breakpoint-Präfix dazukommen. Aus unserem p5-Grid: 

<div class="grid grid-cols-1 gap-6 sm:grid-cols-2 lg:grid-cols-3">

Das liest man von links nach rechts als "zuerst diese Regel, dann ab dieser Breite jene Regel":

grid-cols-1gilt immer — Grundeinstellung ohne Präfix (mobile), eine Spalte
sm:grid-cols-2ab 640px Fensterbreite: zwei Spalten
lg:grid-cols-3ab 1024px Fensterbreite: drei Spalten

Die Standard-Breakpoints von Tailwind:

sm≥ 640px — z.B. grosses Smartphone quer, kleines Tablet
md≥ 768px — Tablet
lg≥ 1024px — kleiner Laptop
xl≥ 1280px — Desktop
2xl≥ 1536px — grosser Desktop

Wichtig: kein Präfix bedeutet nicht "nur mobil"

grid-cols-1 ohne Präfix gilt auf allen Bildschirmgrössen — so lange keine spätere, passende Präfix-Klasse (sm:, lg:, …) sie für grössere Breiten überschreibt. Deshalb reicht es, nur die Änderungen mit Präfix zu versehen.

3. Zustände: die Präfixe hover: focus: active:

Genauso wie Breakpoint-Präfixe funktionieren Zustands-Präfixe: sie wenden eine Utility-Klasse nur an, wenn sich das Element in genau diesem Zustand befindet — CSS-Pseudoklassen als Klassennamen-Präfix. 

<button class="bg-blue-600 hover:bg-blue-700 active:bg-blue-800
               focus:outline-none focus:ring-2 focus:ring-blue-400">
  Click me
</button>
bg-blue-600Grundzustand — normale Hintergrundfarbe
hover:bg-blue-700beim Darüberfahren mit der Maus etwas dunkler
active:bg-blue-800während des Klicks noch dunkler
focus:ring-2bei Tastatur-Fokus (Tab-Taste) ein sichtbarer Ring statt des Browser-Standard-Outlines

Diese Präfixe lassen sich mit den Breakpoint-Präfixen kombinieren, z.B. lg:hover:bg-blue-700 — wirkt nur ab der lg-Breite beim Hover.

4. Häufige Utility-Kategorien im Überblick

Eine kleine Auswahl, um Muster in Klassennamen leichter zu erkennen:

p-4, px-4, py-2, m-2, gap-6Abstände: padding, margin, Zwischenraum in Flex/Grid
bg-*, text-*, border-*Farben für Hintergrund, Text, Rahmen (z.B. bg-blue-600, text-white)
flex, grid, grid-cols-3, items-center, justify-betweenLayout: Flexbox & Grid
rounded-md, shadow-smabgerundete Ecken, Schatten
transition-colors, duration-200weiche Übergänge zwischen Zuständen
hidden, block, relative, absoluteSichtbarkeit & Positionierung
Zum Ausprobieren
  • Öffnet index.html aus der p5-Demo und sucht dort je eine Klasse aus jeder Kategorie oben.
  • Ändert testweise bg-blue-600 auf bg-blue-600 → bg-rose-600 und beobachtet, was sich ändert.
  • Fügt einem beliebigen Button md:text-lg hinzu — was passiert beim Verändern der Fensterbreite?
Mitnahme Utility-Klassen folgen dem Muster eigenschaft-wert, Breakpoint-Präfixe (sm:, md:, lg:) sind mobile-first additiv, Zustands-Präfixe (hover:, focus:) wenden Klassen nur in diesem Zustand an, und peer/group lassen Elemente auf den Zustand von Geschwistern oder Eltern reagieren — ganz ohne eigenes CSS.
