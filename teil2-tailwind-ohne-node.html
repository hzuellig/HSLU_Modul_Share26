CSS Frameworks - Tailwind ohne Node

Utility-First-CSS live im Browser ausprobieren — mit nur einer einzigen Zeile HTML, ganz ohne Installation.

1. Kurzer Rückblick: CSS-Frameworks

Tailwind ist nicht das erste Werkzeug, das versucht, wiederkehrende Layout-Probleme zu lösen. Die immer gleichen Aufgaben — Spalten anordnen, Abstände vereinheitlichen, auf Mobile reagieren — hat schon vor Tailwind eine ganze Reihe von Frameworks angegangen, nur mit unterschiedlichen Ansätzen:

seit ca. 2011

960.gs, Bootstrap & Grid-Systeme

Die Seite wird gedanklich in z.B. 12 gleich breite Spalten eingeteilt. Man "belegt" damit Spalten statt sie selbst zu berechnen: 

<div class="row">
  <div class="col-md-4">...</div>
  <div class="col-md-8">...</div>
</div>

960 Grid System: https://960.gs/

col-md-4 = "4 von 12 Spalten, ab der Grösse md". Bootstrap lieferte zusätzlich fertige Komponenten (Buttons, Navbars, Modals) inkl. eigenem JavaScript — ganze Seiten sahen dadurch oft sehr ähnlich aus ("bootstrap-y").

seit ca. 2009

Flexbox & (später) CSS Grid

Der Browser selbst bekam eingebaute Layout-Systeme (display: flex, display: grid) — kein Framework mehr nötig, um Spalten/Zeilen zu bauen. Das ist die Grundlage, auf der auch Tailwind aufbaut (flex, grid-cols-3 sind letztlich dünne Wrapper um genau diese Browser-Features).

Bootstrap: https://getbootstrap.com/
Foundation: https://get.foundation/

seit ca. 2017

Utility-First (Tailwind & Co.)

Statt fertiger Komponenten wie bei Bootstrap gibt's nur noch die kleinsten Bausteine (p-4, flex, text-white) — man baut sein eigenes Design daraus zusammen, statt Bootstraps Vorgaben zu übernehmen. Dadurch sehen Tailwind-Seiten sich nicht zwangsläufig ähnlich, anders als viele Bootstrap-Seiten früher.

Tailwind: https://tailwindcss.com/

Das Muster dahinter Jede Generation löst dasselbe Grundproblem — "wiederkehrende Aufgaben nicht jedes Mal neu erfinden" — nur auf einer anderen Ebene: erst fertige Grid-Klassen, dann eingebaute Browser-Layouts, dann Utility-Klassen. Das Swiss Confederation Designsystem, das wir gleich in Teil 4 anschauen, ist genau so eine Sammlung von wiederkehrenden Patterns — nur eben spezifisch für Bundes-Webseiten.

2. Tailwind Utility-First: viele kleine Klassen statt eigenem CSS

Statt .card { padding: 16px; } ins CSS zu schreiben, kombiniert man direkt im HTML fertige Klassen: p-4 für Padding, flex für Flexbox, bg-red-600 für eine Hintergrundfarbe. Für Responsive gibt's Präfixe wie md: — dieselbe Idee wie die Media Query aus Teil 1, nur als fertige Klasse.

Der offizielle Tailwind Play CDN kompiliert Utility-Klassen live im Browser. Ein einziges <script>-Tag reicht: 

<script src="https://cdn.tailwindcss.com"></script>

Aber: das ist bewusst nur zum Lernen/Prototypen gedacht.

  • Kompiliert bei jedem Seitenaufruf neu (langsamer als eine fertige Datei)
  • Keine echte Projekt-Konfiguration (eigene Farben, Design-Tokens, …)
  • Tailwind selbst rät ausdrücklich von Produktiveinsatz ab

4. Vorher/Nachher: Teil 1 vs. Teil 2

Gleiches Verhalten, unterschiedlicher Ansatz:

Teil 1 — eigenes CSS

.grid {
  display: grid;
  grid-template-columns: 1fr;
  gap: 12px;
}
@media (min-width: 700px) {
  .grid {
    grid-template-columns: repeat(3, 1fr);
  }
}

Teil 2 — Tailwind-Klassen

<div class="grid grid-cols-1
            md:grid-cols-3 gap-3">
  ...
</div>

<!-- kein eigenes CSS nötig -->

5. Startpunkt für eigene Experimente

Dieses Grundgerüst kannst du 1:1 kopieren und lokal als .html-Datei speichern und im Browser öffnen — läuft sofort, ganz ohne Server:

<!DOCTYPE html>
<html lang="de">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>Tailwind Playground</title>
  <script src="https://cdn.tailwindcss.com"></script>
</head>
<body class="bg-gray-50 p-6">

  <h1 class="text-2xl font-bold mb-4">Hallo Tailwind</h1>

  <div class="grid grid-cols-1 md:grid-cols-3 gap-4">
    <div class="bg-white border rounded-lg p-4">Karte 1</div>
    <div class="bg-white border rounded-lg p-4">Karte 2</div>
    <div class="bg-white border rounded-lg p-4">Karte 3</div>
  </div>

</body>
</html>
Mitnahme aus Teil 2 Du kannst direkt im Browser mit Tailwind-Klassen experimentieren, verstehst das Utility-Prinzip und kennst die Grenzen des Play-CDN.
